Paso 0 · Preparación

Revisar el proyecto

Abre la carpeta del proyecto en VS Code y confirma que existen los archivos de despliegue.

BACK-END/
  package.json
  prisma/schema.prisma
  prisma/migrations/
FRON_END/
render.yaml
.github/workflows/ci-cd.yml

No subas BACK-END/.env, certificados privados ni archivos de uploads.

Paso 1 · Base de datos

Confirmar tu PostgreSQL existente

En Render abre tu PostgreSQL y localiza las dos URLs de conexión. No las publiques ni las envíes por chat.

External Database URLSe usa únicamente en tu computadora, pruebas locales o herramientas externas. No la uses en el Web Service de Render.
Internal Database URLSe usa en la variable DATABASE_URL del Web Service de Render. Esta es la que debes ingresar en el Paso 5.
Paso 2 · Configuración local

Probar desde tu computadora

En BACK-END/.env, si quieres probar contra Render desde tu PC, ingresa aquí la External Database URL. Para producción no copies este archivo al repositorio.

DATABASE_URL=<External Database URL, solo si pruebas localmente>
JWT_SECRET=<secreto local>
NODE_ENV=development
ORIGEN_FRONTEND=
cd BACK-END
npm ci
npx prisma generate
npx prisma migrate deploy
npm run lint
No pegues la Internal ni la External URL en GitHub. Ambas contienen credenciales.
Paso 3 · GitHub

Subir el proyecto sin secretos

Crea un repositorio vacío y sube el proyecto desde su raíz. El workflow ejecutará las pruebas con una base PostgreSQL temporal.

git init -b main
git add .
git commit -m "Preparar despliegue de plataforma de incidentes"
git remote add origin https://github.com/<usuario>/<repositorio>.git
git push -u origin main
Paso 4 · Render

Crear el Web Service

  1. En Render selecciona New + → Web Service.
  2. Conecta el repositorio de GitHub.
  3. Si Render detecta el Blueprint, usa render.yaml. Si lo configuras manualmente, usa estos valores:
Root Directory: BACK-END
Build Command: npm ci && npx prisma generate && npx prisma migrate deploy
Start Command: npm start
Health Check Path: /salud
Paso 5 · Variables de Render

Este es el momento de ingresar la URL

En Render abre el Web Service → Environment → Environment Variables. Aquí debes ingresar la Internal Database URL de tu PostgreSQL existente.

DATABASE_URL=<Internal Database URL de tu base existente>
NODE_ENV=production
JWT_SECRET=<secreto largo y privado>
ORIGEN_FRONTEND=
Respuesta directa: la Internal Database URL se ingresa aquí, en DATABASE_URL del Web Service de Render. La External Database URL solo se usa desde fuera de Render.

Deja ORIGEN_FRONTEND vacío si el frontend se sirve desde este mismo servicio. Si lo publicas en Vercel, escribe su URL completa, por ejemplo https://mi-frontend.vercel.app.

Paso 6 · Verificación

Comprobar producción

Cuando Render termine el despliegue, abre la URL pública:

https://<tu-servicio>.onrender.com/salud

La respuesta correcta es:

{ "estado": "ok", "baseDeDatos": "conectada" }

Después inicia sesión y prueba crear, editar, filtrar y eliminar un incidente. La eliminación requiere un usuario administrador.

Paso 7 · CD

Activar despliegue continuo

En Render crea un Deploy Hook. En GitHub ve a Settings → Secrets and variables → Actions y agrega:

RENDER_DEPLOY_HOOK=<URL privada del Deploy Hook>

Cada push a main ejecutará PostgreSQL temporal, migraciones, pruebas y lint. Solo si todo pasa, Actions solicitará el despliegue en Render.
